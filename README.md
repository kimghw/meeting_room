# KRS 회의실 예약 (크롬·엣지 확장)

eclass 회의실 현황을 사이드 패널에서 **시간 단위**로 보고, 빈 칸을 끌어서 범위를 고른 뒤 바로 예약합니다.

## 설치

누가 쓰든 절차가 같습니다. **코드에 고칠 개인 값은 없습니다** — 아래 [사람마다 다른 것](#사람마다-다른-것--따로-설정하지-않습니다) 참고.

1. 받기 — `git clone https://github.com/kimghw/meeting_room` (또는 ZIP 으로 받아 풀기)
2. 주소창에 크롬은 `chrome://extensions`, 엣지는 `edge://extensions` → 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 받은 폴더 선택
4. 같은 브라우저에서 **eclass 에 로그인** — 확장은 이 브라우저의 로그인을 그대로 씁니다
5. 툴바의 확장 아이콘을 누르면 사이드 패널이 열립니다

크롬과 엣지 어느 쪽이든 같은 폴더를 그대로 불러옵니다. 확장 코드는 두 브라우저에 공통이고,
다른 것은 아래 다리 등록에서 레지스트리 키 위치와 브라우저를 완전히 끄는 방법뿐입니다.

2번의 "압축해제된 확장 로드" 클릭은 프로그램으로 대신할 수 없습니다. 크로미엄이 일부러 막아 둔 자리라
(기본 프로필은 디버그 포트를 받지 않고, 명령줄이나 CDP 로 올린 확장은 그 세션에만 남습니다) 사람이 한 번 눌러야 합니다.
클릭 없이 쓰고 싶으면 엣지 한정으로 `/bridge shortcut` 이 전용 프로필을 `--load-extension` 으로 띄우는
바로가기를 만들어 줍니다. 대신 그 프로필에서 eclass 에 따로 로그인해야 합니다.

여기까지면 조회·예약·취소·수정·차량 신청이 다 됩니다. **말로 찾기만 추가 설정이 필요합니다** —
아래 [로컬 CLI 연결](#로컬-cli-연결-권장-키-불필요)을 하거나 `설정 및 연결` 에 API 키를 넣으세요.

### 사람마다 다른 것 — 따로 설정하지 않습니다

| 무엇 | 어디서 오나 |
|---|---|
| 로그인한 사람 | 각자 브라우저의 eclass 로그인 |
| 예약자·운전자 이름, 부서, 사번 | 사이트가 신청 폼에 로그인한 사람으로 미리 채워 둔 값을 읽습니다 (`readFormWho`) |
| `내 이름` (내 예약 찾기용) | 이 확장으로 처음 예약할 때 자동으로 기억합니다. `설정 및 연결` 에서 직접 넣어도 됩니다 |
| 확장 ID | 받은 폴더 경로에서 브라우저가 정합니다(크롬·엣지 같은 값). 다리를 등록할 때만 필요합니다 |
| Claude | 각자 PC 에 로그인된 `claude`, 또는 각자의 API 키 |

설정과 활동 로그는 브라우저 프로필마다 따로 저장돼 다른 사람과 섞이지 않습니다.
크롬과 엣지에 둘 다 불러오면 프로필이 달라 설정도 따로 갑니다.

## 사용

- 위쪽에서 날짜를 고르거나 `◀ ▶` 로 하루씩 이동합니다.
- `시간 08 ~ 20` 으로 화면에 보여줄 업무 시간대를 조절합니다(설정은 저장됩니다).
- 격자에서 **연한 초록 = 예약 가능**, **회색 = 사용 중**입니다. 칸에 마우스를 올리면 누가 쓰는지 보입니다.
- 빈 칸을 **클릭하거나 끌어서** 1시간 단위로 범위를 고릅니다. **여러 번 클릭하면 선택이 쌓여** 여러 건을 한꺼번에 예약할 수 있고, 고른 칸을 다시 누르면 빠집니다.
- 아래 예약 폼에 회의주제를 넣고 **예약하기**를 누릅니다.
- `↻` 로 새로고침, `자동` 을 켜면 60초마다 다시 조회합니다. 마지막 조회 시각이 오른쪽에 표시됩니다.
- 왼쪽 위 **지역 버튼**(부산/서울)을 누르면 지역이 바뀝니다. 회의실 목록이 지역별로 다릅니다.
- 회의실 이름 옆 배지는 좌석 수입니다. **내 예약**은 칸 아래 노란 밑줄로 표시됩니다.
- 줄 차례는 사이트 드롭다운이 아니라 **자주 쓰는 순서**입니다 — `제1~제5회의실`, `미팅룸1·2`,
  나머지 순이고, `부산지부 · 스마트홀 · 오션홀` 은 맨 아래에 **접혀** 있습니다.
  접힌 줄의 손잡이를 누르면 펼쳐지고, 그 상태는 저장됩니다(`src/roomorder.js`).
- `회의실 현황` 옆에는 **지금 보고 있는 날짜**와 그날 예약 건수가 붙습니다(회의실 수가 아닙니다 — 날짜가 바뀌어도 그대로라 배지로 쓸모가 없었습니다).
- 상단 **내 예약** 탭에서 내가 예약한 회의실·차량을 한 목록으로 봅니다(아래 참고).
- 패널을 열면 곧바로 **오늘부터 한 달치를 회의실·차량 모두 미리 훑어 둡니다**(아래 참고).
  상태줄 아래 가는 막대가 진행 상황이고, 다 되면 `한 달 준비됨 · 9/16~10/15` 로 바뀝니다.
  막대를 누르면 처음부터 다시 훑습니다.

### 차량 이용

상단 **차량** 탭에서 날짜별 차량 이용 현황을 보고, **신청·취소·수정까지** 합니다.
회의실과 똑같이 빈 칸을 끌어 고르고 아래 폼을 채워 보냅니다.

차량 폼은 회의실과 요구하는 것이 다릅니다. **행선지가 필수이고 사용목적은 아닙니다**
(사이트의 `fnSaveCheck()` 가 실제로 그렇게 막습니다 — 목록 페이지에 죽은 채 남아 있는
`fnSave()` 는 사용목적도 요구하지만 진짜 신청 폼은 보지 않습니다). 사이트보다 엄격하게
막으면 사이트에서는 되는 일이 이 확장에서만 안 되므로, 사이트가 막는 것만 막습니다.

신청 폼은 목록이 아니라 **팝업 페이지**(`Admin_View_New.aspx?CARIDX=..&SDATE=..`)에 있고,
**차량은 폼에서 고르는 게 아니라 주소가 정합니다**(`DDL_CARNAME` 옵션이 하나뿐입니다).

차량 표는 로그인해야 볼 수 있어 컬럼 위치를 박아두지 않고, **행 내용을 보고**
어느 칸이 시간이고 어느 칸이 차량인지 찾아냅니다(`src/grid.js`).
이 감지기는 회의실 실제 페이지로 검증했습니다 — 지역·회의실·시간·상태 네 컬럼을
정확히 찾아냅니다. 차량 화면에서 못 찾으면 **확인 불가**로 표시되고,
그때는 차량 탭에서 `설정 및 연결 → 페이지 구조 캡처`를 눌러 전달해 주시면 맞추겠습니다.

### 예약 수정

사이트에는 **예약을 옮기는 기능이 없습니다.** 그래서 이 확장의 수정은
**기존 건을 취소하고 새 시간으로 다시 넣는 것**이고, 실패하면 되돌립니다.
내 예약 탭에서 `수정` 을 누르면 그 날짜로 이동하고, 격자에서 새 시간을 고르면 실행됩니다.

되돌리기에는 규칙이 있습니다(`src/modify.js`).

| 어디서 실패했나 | 무엇을 하나 |
|---|---|
| 취소가 실패 | 기존 예약을 건드리지 않았으므로 그대로 둡니다. 새 예약을 **시도하지 않습니다.** |
| 취소 성공 → 새 예약 성공 | 끝. |
| 취소 성공 → 새 예약이 **제출조차 못 됨** | 원래 시간으로 되살립니다. |
| 취소 성공 → 새 예약이 **제출은 됐는데 확인이 안 됨** | **되돌리지 않습니다.** |

마지막 칸이 중요합니다. 저장이 실제로 됐을 수도 있어서, 원래 예약을 되살리면 **이중 예약**이
됩니다. 사람이 한 번 보면 끝나는 일이지만, 이중 예약은 남이 못 쓰는 칸을 말없이 하나 더
만듭니다. 그래서 이때는 "모르겠으니 사이트에서 확인해 달라"고 말합니다.

차량을 수정할 때는 **행선지를 다시 입력**해야 합니다. 차량 목록의 상세 행에는 사용목적만
남고 행선지가 없어서, 되돌릴 때 쓸 값을 읽어올 데가 없습니다. 화면에도 그렇게 적어 둡니다.

`이어붙이기`(내 예약 옆 빈 칸을 골라 시간을 늘리는 것)도 같은 엔진을 씁니다.

### 내 예약

상단 **내 예약** 탭은 고른 날부터 며칠간(7·14·21일 / **한 달**, 기본값)을 훑어 **내가 예약한
회의실과 차량을 한 목록으로** 보여줍니다. 한 줄을 누르면 그 날짜의 회의실/차량 화면으로 갑니다.
지역은 가리지 않습니다 — 부산·서울 예약이 모두 나옵니다.

패널을 열 때 이미 한 달을 미리 훑어 두므로 보통은 기다릴 것이 없습니다. 아직 훑는 중이면
**담기는 대로 목록이 차오릅니다** — 서른 날을 다 기다린 뒤에야 첫 줄이 보이면
아무것도 안 하는 것처럼 보이기 때문입니다.

내 것인지 어떻게 아느냐가 문제입니다. **사이트는 로그인한 사람이 누구인지 화면 어디에도
적어주지 않습니다**(숨은 입력칸에도 없습니다). 그래서 신호 셋을 합쳐 보고, 항목 오른쪽에
무엇을 보고 그렇게 판단했는지 적어 둡니다.

| 근거 | 뜻 |
|---|---|
| (표시 없음) | 사이트가 그 줄에 **수정·삭제 버튼**을 붙였습니다. 본인 건에만 붙으므로 가장 확실합니다. |
| `이름 일치` | 예약자 이름이 `설정 및 연결` 에 넣어둔 **내 이름**과 같습니다. |
| `내가 넣음` | 이 확장으로 넣어 **확인까지 끝난** 예약 기록과 겹칩니다. |

이름은 이 확장으로 예약이 확인되면 그 줄의 예약자 이름으로 **자동으로 채워집니다**
(같은 회의주제일 때만 — 제출 사이에 남이 같은 칸을 채간 경우와 섞이면 안 되므로).
직접 넣어도 됩니다. 이름을 알면 회의실·차량 격자의 **내 예약 밑줄**도 같이 정확해집니다.

훑는 동안 못 읽은 날은 **결과에서 빼고 몇 일이 빠졌는지 말합니다.** 못 읽은 날을 조용히
넘기면 "내 예약이 없다"는 거짓말이 되기 때문입니다. 아무것도 못 찾았을 때도
"없습니다"가 아니라 **왜 못 찾았을 수 있는지**를 함께 보여줍니다.

훑기는 **하루에 요청 한 번**입니다. `loadDay` 는 날짜마다 페이지를 새로 받지만,
`src/site.js` 의 `scanDays` 와 `src/rentcar.js` 의 `scanCarDays` 는 **한 번 연 화면을 들고
날짜만 옮깁니다.** 월 달력에 0건이라고 찍힌 날은 아예 옮기지 않고 건너뜁니다 —
사이트가 스스로 센 숫자라 믿을 수 있습니다.

### 한 달 미리 훑기

패널이 열리면 보고 있는 탭을 먼저 띄운 다음, **오늘부터 30일을 회의실·차량 두 벌로 한 번
훑어 `src/monthcache.js` 의 보관소에 담습니다.** 세 탭이 이 한 벌을 나눠 씁니다.

- **내 예약** 은 직접 훑지 않고 보관소에서 그 기간을 꺼내 씁니다. 훑기는 한 번에 하나만 돌아서,
  내 예약 탭으로 열려도 미리 훑기와 겹쳐 두 배로 두드리는 일이 없습니다.
- **회의실·차량** 은 날짜를 옮기면 담아 둔 것으로 **격자를 먼저 그립니다.** 그래서 ◀▶ 를
  눌러도 빈 화면을 보지 않습니다. 예약 목록만으로는 빈 회의실을 알 수 없어서,
  훑을 때 **회의실(차량) 목록도 함께 담아 둡니다.**

담아 둔 화면은 **보기 전용**입니다. 예약·취소는 사이트 화면의 ViewState 손잡이가 있어야 하는데
훑기는 그것을 남기지 않습니다. 그래서 살아 있는 조회가 끝날 때까지 격자는 흐리게 잠겨 있고,
그 사이에 예약 버튼을 누르면 "잠시 뒤 다시" 라고 말합니다.

담긴 값에는 **언제 읽었는지**가 붙습니다. 캐시로 그린 화면에는 `미리 훑어 둔 현황(3분 전)`
처럼 함께 적고, 10분이 지난 기록은 다음에 부를 때 다시 읽습니다. 묵은 현황을 지금 것처럼
보여주면 이미 찬 칸을 "예약 가능"으로 칠하게 되는데, 이 앱에서 가장 나쁜 실패입니다.
예약·취소한 날은 그 자리에서 보관소에서 버려 다음에 볼 때 다시 읽습니다.

지역을 바꿔도 담아 둔 예약은 그대로 씁니다 — 예약 목록에는 전 지역이 들어 있고,
지역마다 다른 것은 **회의실 목록뿐**이라 그것만 따로 기억해 둡니다.

## 말로 찾는 회의실/차량

맨 아래 입력칸에 이렇게 적으면 됩니다. **회의실 탭과 차량 탭에서 모두** 씁니다 —
보고 있는 탭에 맞춰 회의실을 찾거나 차량을 찾습니다.

```
9월 20일부터 27일 사이 8시부터 12시까지 10명
내일 오후에 회의실 아무거나
다음 주 화요일 2시간짜리 서울 회의실
내일 오후 2시부터 3시간 쓸 차량
```

Claude 가 조건을 해석해 날짜를 하루씩 조회하고, 조건에 맞는 빈 시간대를 목록으로 보여줍니다.
**항목을 누르면 그 탭·날짜·지역으로 옮겨 해당 칸이 선택**되므로 회의주제(차량은 행선지)만
적고 예약하면 됩니다. 다른 탭에서 찾은 것을 눌러도 그 탭으로 돌아가고, 접어 둔 회의실이
걸리면 저절로 펼쳐집니다.

차량에는 좌석 정보가 없어 **인원 조건은 무시**하고, 뺐다는 것을 결과 줄에 적어 줍니다.

해석은 세 단계로 내려갑니다. 결과에 어느 것을 썼는지 `[로컬 CLI]` 처럼 표시됩니다.

1. **로컬 Claude Code CLI** — API 키가 필요 없습니다. 이미 로그인된 `claude` 를 그대로 씁니다.
2. **Anthropic API 키** — `설정 및 연결` 에 넣으면 씁니다(이 브라우저에만 저장).
3. **규칙 해석** — 위 둘 중 하나가 붙어 있는데 호출이 실패하면 흔한 문장은 규칙으로 처리합니다.

**둘 다 없으면 입력칸이 잠깁니다** — 플레이스홀더에 `claude가 연결되지 않았습니다` 라고 적히고
버튼도 눌리지 않습니다. 여기서 말하는 "연결" 은 **확장이 claude 에 닿을 수 있는가**이지
PC 에 claude 가 깔려 있는가가 아닙니다. 아래 `로컬 CLI 연결` 등록을 하거나 API 키를 넣으면 풀립니다.

한 번 검색할 때 날짜 수만큼 사이트를 조회하므로 최대 14일까지만 봅니다.
현황을 확신할 수 없는 날은 결과에서 빼고 몇 일이 빠졌는지 알려줍니다.

### 로컬 CLI 연결 (권장, 키 불필요)

브라우저 확장은 로컬 프로그램을 직접 실행할 수 없어 네이티브 메시징 다리를 씁니다.
**이 등록은 선택이 아니라 필수입니다** — PC 에 `claude` 가 깔려 있고 로그인까지 돼 있어도,
등록하지 않으면 확장은 거기에 닿지 못합니다. 배지가 `없음` 으로 뜨고 말로 찾기 칸도 잠깁니다.

1. `chrome://extensions`(엣지는 `edge://extensions`) 에서 이 확장의 **ID** 를 복사
2. `powershell -ExecutionPolicy Bypass -File native\install.ps1 -ExtensionId <ID>`
3. 브라우저를 완전히 종료 후 재시작 → `설정 및 연결` 에 `로컬 Claude CLI: 연결됨`

`install.ps1` 은 크롬 키(`HKCU\Software\Google\Chrome\NativeMessagingHosts`)와
엣지 키(`HKCU\Software\Microsoft\Edge\NativeMessagingHosts`)에 같은 매니페스트를 한 번에 겁니다.
두 브라우저 모두 origin 이 `chrome-extension://<ID>/` 이고 같은 폴더면 ID 도 같아 매니페스트 하나로 됩니다.
설치되지 않은 쪽 키는 놀 뿐 해가 없습니다.

**엣지는 창을 다 닫아도 끝나지 않습니다.** "시작 부스트" 와 "Microsoft Edge 가 닫혀 있을 때도 백그라운드 확장 및 앱
계속 실행" 이 기본으로 켜져 있어 `msedge.exe` 가 남고, 창을 다시 열면 그 프로세스가 그대로 쓰여 새 등록을 읽지 못합니다.
작업 관리자에서 `msedge.exe` 를 전부 끝내거나 `edge://settings/system` 에서 두 설정을 끈 뒤 다시 여세요.
`/bridge` 는 브라우저 본체가 등록보다 먼저 떴는지 시각을 비교해 재시작이 정말 필요한지 말해 주고,
창이 하나도 없을 때는 `/bridge restart edge` 가 남은 본체를 끝내고 다시 띄워 줍니다(창이 있으면 끊지 않습니다).

이 절차와 점검은 `/bridge` 스킬이 대신합니다 — `/bridge` 로 여섯 항목을 한 번에 보고,
`/bridge install` 로 ID 계산·등록·왕복 확인까지 합니다(`.claude/skills/bridge`).

ID 는 **불러온 폴더 경로에서 나옵니다.** 폴더를 옮기면 ID 가 바뀌니 다시 등록해야 합니다.
브라우저를 `--user-data-dir` 로 따로 띄워 써도 등록은 `HKCU` 에 들어가므로 프로필과 무관하게 먹습니다.

확장이 임의의 명령을 실행할 수는 없습니다. `claude` 를 부르는 작업은 `parse` 와 `diagnose` 둘뿐이고
(그 밖에는 연결 확인 `ping` 과 호출 기록 읽기 `logs`),
시스템 프롬프트도 호스트 파일에 고정돼 있어, 확장이 보내는 것은 입력 텍스트뿐입니다.
접근은 등록한 확장 ID 로만 제한됩니다.

기본 에이전트 프롬프트를 빼서(`--exclude-dynamic-system-prompt-sections`)
호출당 캐시 토큰이 38K → 4.2K, 비용이 $0.078 → $0.012 로 줄었습니다.
해제는 `native\uninstall.ps1` 입니다(크롬·엣지 키 둘 다 지웁니다).

다리는 `claude` 를 부를 때마다 `native\logs\<날짜>.jsonl` 에 한 줄 남깁니다(입력·결과·비용·걸린 시간,
실패면 종료 코드와 stderr). 14일이 지난 파일은 지웁니다. `/bridge log` 로 최근 기록을 볼 수 있습니다.

## 활동 로그

패널 아래 `활동 로그` 칸에 예약·취소·수정·이어붙이기, 말로 찾기, 조회·훑기 실패, 캡처,
다리 연결 상태가 남습니다. 이 브라우저(`chrome.storage`)에 최근 500건까지 둡니다.
같은 일이 이어지면 새 줄 대신 횟수만 올립니다(자동 갱신이 같은 실패로 목록을 채우지 않게).

- **로그 복사** — 확장 기록 전부에 다리 기록(최근 30건)과 환경(버전·탭·다리·API 키 유무)을 붙여
  클립보드에 넣습니다. 문제가 생기면 이것을 그대로 붙여 넣으면 됩니다.
- **파일로 저장** — 같은 내용을 다운로드 폴더에 `krs-log-<시각>.txt` 로 저장합니다.
- **비우기** — 두 번 눌러야 지웁니다. 이 브라우저 기록만 지우고 `native\logs` 는 그대로 둡니다.

예약이 실패하면 응답에서 **보낸 값과 응답에 남은 값의 차이**만 추린 요약(`src/diagnose.js`)을
그 기록에 같이 남깁니다. 예전에 다운로드 폴더에 따로 쓰던 `meetingroom-save-response.txt` 는 이것으로 대신합니다.
기록에는 회의 주제·이름·입력한 문장이 들어 있고, API 키는 남기지 않습니다.

로그인이 안 되어 있으면 안내와 함께 eclass 링크가 뜹니다. 로그인 후 다시 조회하세요.

### 실제 크롬·엣지에서 (CDP)

jsdom 이 흉내 낼 수 없는 것 — 확장이 정말 로드되는지, 사이드패널이 JS 오류 없이 뜨는지,
살아 있는 사이트를 실제로 읽는지 — 는 브라우저를 띄워 확인합니다.

```
chrome.exe --remote-debugging-port=9333 --user-data-dir=<빈 폴더>
node test/cdp/run.mjs
```

엣지도 같은 하네스로 봅니다. `msedge.exe` 에 같은 인자를 주면 되고, 다른 포트를 쓰면 `CDP_PORT` 로 알려줍니다.
2026-09-16 엣지 153 에서 확장 ID 가 크롬과 같게 나오고 사이드패널 검사 11건이 통과한 것을 확인했습니다.

**크롬 136+ 는 기본 프로필에 디버그 포트를 붙여주지 않습니다.** 반드시 따로 `--user-data-dir`
을 줘야 하고, 그러면 쿠키 항아리가 달라져 **그 창에서 eclass 에 한 번 로그인**해야 합니다.
로그인해야 되는 검사는 로그인이 없으면 `skip` 으로 찍고 이유를 말합니다 — 조용히 통과시키면
"확인했다"는 거짓말이 되기 때문입니다.

**크롬 137+ 는 명령줄 `--load-extension` 을 무시합니다.** 그래서 하네스가 CDP 의
`Extensions.loadUnpacked` 로 직접 올립니다(경로는 역슬래시를 받지 않고 슬래시여야 합니다).

사이트에 **쓰지는 않습니다.** 신청 폼을 열어 구조를 읽을 뿐 저장 버튼은 누르지 않습니다.

`test/fixtures/` 는 2026-09-16 로그인 상태에서 받은 진짜 페이지입니다(`rentcar-save-500.html` 은 저장이 터졌을 때의 실제 오류 화면).
파서를 고칠 때 추측 대신 이 파일로 확인할 수 있습니다.

## 사이트 구조 (2026-09-16 캡처 기준)

조회 화면은 **Telerik RadGrid**(`RG_MAIN_ctl00`)이고 헤더 행이 `display:none` 에 `&nbsp;` 뿐이라
헤더 이름으로는 컬럼을 찾을 수 없습니다. `colgroup` 으로 위치가 고정돼 있어 인덱스로 읽습니다.

| 위치 | 내용 |
|---|---|
| 2 | 지역 (부산/서울) |
| 3 | 회의실명 (`미팅룸1(1층)-8석`) |
| 4 | 시간 (`09:00~18:00`) |
| 5 | 승인 상태 |
| 다음 행 | 중첩 표에 회의주제·예약자(부서) |

**회의실 목록은 지역별로 따로 내려옵니다.** `DDL_REGION` 을 바꾸면 포스트백으로
`DDL_ROOMNAME` 이 그 지역 것으로 다시 채워집니다(부산 14곳 / 서울 3곳).
그래서 패널에 지역 선택기가 있고, 지역을 바꾸면 다시 조회합니다.

좌석 수와 층은 회의실 이름에서 뽑습니다 (`-8석` → 8석 배지, `(11층)` → 11층).

예약 폼은 같은 페이지 안의 숨겨진 `div_write` 입니다. 인원 입력칸은 **없습니다**.

| 필드 | 이름 |
|---|---|
| 지역 / 회의실 | `DDL_REGION` / `DDL_ROOMNAME` |
| 날짜 | `DP_ROOMDATE`, `DP_ROOMDATE$dateInput` + **ClientState**(아래) |
| 시작 / 종료 | `DDL_ROOMSHOUR`+`DDL_ROOMSMINUTE` / `DDL_ROOMEHOUR`+`DDL_ROOMEMINUTE` |
| 반복 | `RB_REPEAT` (N = 설정 안 함) |
| 회의주제 | `TXT_TITLE` |
| 저장 | `BTN_SAVE` (이미지 버튼 → `.x`/`.y` 로 제출) |

분은 10분 단위만, 종료는 23:50 까지만 받습니다.

차량 취소는 **회의실과 경로가 다릅니다.** 회의실은 `lbDelete` 를 누릅니다. 차량은 내가 넣은
건의 행 끝에 **취소 submit 버튼**이 붙습니다(2026-09-30 실제 화면에서 확인).

```html
<input type="submit" name="RG_MAIN$ctl00$ctl06$Detail10$ctl04$BTN_DEL"
       value="취소" onclick="return fnDelete();">
```

`fnDelete()` 는 확인창일 뿐이라, **그 이름을 얹어 포스트백하면 취소 버튼을 누른 것과 같습니다.**
버튼이 그 건의 행 안에 있으니 어느 건을 지우는지 헷갈릴 수도 없습니다.

페이지에는 `fn_del(idx, group)`(→ `HF_DEL_YN`/`HF_IDX`/`HF_GROUP_IDX` + `__doPostBack`)도
남아 있지만 **실제 화면이 쓰는 길이 아닙니다.** 그 인자만 찾다가 못 찾아서 한동안 차량 취소가
통째로 막혀 있었습니다(`del = null` → 취소 버튼 비활성). 지금은 submit 버튼을 먼저 보고,
없을 때만 옛 길로 내려갑니다. 이 버튼은 **본인 건에만** 붙으므로 "내 예약" 판정에도 씁니다.

### 날짜 칸은 글자만 채우면 안 먹는다

예약 폼의 날짜는 Telerik `RadDatePicker` 입니다. `DP_ROOMDATE` 와 `DP_ROOMDATE$dateInput`
두 글자 칸에 날짜를 넣어 보내도 **서버가 무시하고 ViewState 에 있던 날짜(보통 오늘)를 씁니다.**
값은 숨은 `DP_ROOMDATE_dateInput_ClientState` 의 JSON 에서 읽기 때문입니다.

```
{"enabled":true,"emptyMessage":"","validationText":"2026-09-19-00-00-00",
 "valueAsString":"2026-09-19-00-00-00","lastSetTextBoxValue":"2026-09-19"}
```

게다가 목록 날짜(`LB_DATE`)를 옮겨도 예약 폼 날짜는 따라오지 않습니다. 목록은 달력의
`CAL_MAIN_SD` 로 옮기는데, 그러면 서버의 선택 변경 처리기가 돌지 않아 폼 날짜가 그대로입니다.
사이트의 `예약하기` 버튼(`fn_write()`)도 그냥 `div_write` 를 펼치기만 할 뿐 날짜를 넣지 않습니다.

그래서 `src/parse.js` 의 `telerikDateFields()` 가 글자 칸과 ClientState,
달력 선택일(`DP_ROOMDATE_calendar_SD`)을 한꺼번에 만들고,
`reserve()` 는 **저장 직전에 폼 날짜가 정말 요청한 날짜인지 확인한 뒤에만 제출합니다.**
다르면 제출하지 않고 멈춥니다 — 조용히 오늘 날짜로 예약되는 것보다 낫기 때문입니다.

### 차량 신청 폼 (2026-09-16 캡처 기준)

`Admin_View_New.aspx?CARIDX=<차량>&SDATE=<날짜>` 팝업. `test/fixtures/rentcar-form-2026-09-16.html`
이 실제 캡처입니다. 여기 오기 전까지 필드 이름은 전부 추측이었고, **그 추측은 대부분 틀렸습니다** —
목록 페이지의 죽은 `fnSave()` 는 `TXT_TITLE`/`TXT_PLACE`/`TXT_DRIVER` 라고 했지만
진짜 폼은 `txtTitle`/`txtPlace`/`txtDriver` 입니다. `DDL_CARNAME` 하나만 맞았습니다.

| 필드 | 이름 |
|---|---|
| 차량 / 지역 | `DDL_CARNAME` / `DDL_REGION` (둘 다 옵션 1개 — 차량은 주소가 정한다) |
| 시작일 / 종료일 | `txtSdate` / `txtEdate` (Telerik, **표기가 회의실 폼과 다르다** — 아래) |
| 시작 시/분 | `ddlStimeH` + `ddlStimeM` |
| 종료 시/분 | `ddlEtimeH` + `ddlEtimeM` |
| 사용자 / 부서 / 사번 | `txtDriver` / `txtDriverDeptName` / `hidDriverID` (사이트가 채워서 내려준다) |
| 동승자 / 행선지 / 사용목적 | `txtPassenger` / `txtPlace` / `txtTitle` |
| 저장 | `ibtnITSave` (이미지 버튼 → `.x`/`.y`) |

시 값은 `9` 이지 `09` 가 아니고, 분은 `0`/`10`/…/`50` 입니다. 0 을 채워 보내면 서버가
조용히 첫 항목을 씁니다. 그래서 `src/carform.js` 는 **드롭다운이 실제로 가진 옵션 값**을 씁니다.

#### 날짜 칸 표기는 폼마다 다르다 (HTTP 500 의 원인이었음)

같은 Telerik 날짜 피커인데 **글자 칸 표기가 다릅니다.**

| | `$dateInput` 값 |
|---|---|
| 회의실 예약 폼 `DP_ROOMDATE` | `2026-09-16` |
| 차량 신청 폼 `txtSdate` | `2026-09-16-00-00-00` |

회의실 표기를 차량 폼에 밀어 넣으면 저장이 통째로 터집니다 — 사이트가 이렇게 답합니다.

```
HTTP 500  Text property cannot be set. 문자열이 유효한 DateTime으로 인식되지 않습니다.
```

브라우저가 실제로 보내는 본문을 CDP 로 가로채 대조해서 찾았습니다. 브라우저는 그 칸을
`2026-09-16-00-00-00` 로 보내고, `_dateInput_ClientState` 와 `_calendar_SD` 는 **비운 채**
보냅니다. 그래서 `telerikDateFields()` 는 **그 칸이 지금 들고 있는 생김새를 지키고 날짜만**
바꾸며, 폼이 이미 그 날짜면(신청 폼은 `?SDATE=` 로 여니 대부분 그렇습니다) 아예 건드리지 않습니다.

`test/fixtures/rentcar-save-500.html` 이 그때 받은 실제 오류 화면입니다(스택 추적은 잘라냄).
`src/net.js` 의 `describeErrorPage()` 가 여기서 한 줄을 뽑아, 이제 `HTTP 500` 대신
**사이트가 말한 이유**가 화면에 뜹니다.

`fnSaveCheck()` 가 막는 것: 시작일 ≤ 종료일, 같은 날이면 시작시 ≤ 종료시, 사용자·부서 필수,
행선지 필수. 사용목적은 **검사하지 않습니다.**

이름을 여기 박아두지 않고 `src/carform.js` 가 **문서를 보고 찾아냅니다**(`src/grid.js` 가 컬럼을
찾는 것과 같은 방식). 시·분은 옵션이 0~23 인지 10분 단위인지로, 글자 칸은 옆 라벨 글자로 가립니다.
못 찾으면 **제출하지 않고** 무엇을 못 찾았는지 말합니다. 실제로 이 설계 덕분에 추측한 이름이
전부 틀렸는데도 진짜 폼에서 모든 칸을 정확히 찾아냈습니다.

### 사이트가 로그인한 사람을 알려주는 유일한 자리

"사이트는 로그인한 사람이 누구인지 화면 어디에도 적어주지 않는다"는 건 조회 화면 이야기입니다.
**차량 신청 폼은 이름·부서·사번을 채워서 내려줍니다**(`txtDriver`, `txtDriverDeptName`,
`hidDriverID`). 차량을 한 번 신청하면 이름이 저절로 채워지고, 회의실 격자의 내 예약 밑줄도
같이 정확해집니다.

## "예약된 건지 어떻게 아느냐"

이 확장은 **모를 때 모른다고 말합니다.** 칸 상태는 세 가지입니다.

| 표시 | 뜻 |
|---|---|
| 연한 초록 | 예약 가능 (현황을 정확히 읽었고 비어 있음) |
| 회색 | 사용 중 |
| **노란 빗금** | **확인 불가** — 예약 여부를 읽지 못함. 선택되지 않음 |

읽기 결과를 그냥 믿지 않고 **독립적인 근거와 대조**합니다.

- 월 달력에 날짜별 예약 건수가 찍혀 있습니다. 표에서 읽은 건수가 달력 건수와
  다르면 파싱을 놓친 것이므로 **확인 불가**로 처리합니다.
- 화면의 `LB_DATE` 가 요청한 날짜와 같은지 확인합니다. 날짜를 못 옮겼으면 확인 불가입니다.
- 회의실 목록이나 지역을 못 가져와도 확인 불가입니다.

읽기 실패를 "예약 없음"으로 착각해 빈 방이라고 잘못 안내하는 일을 막기 위해서입니다.

예약도 마찬가지입니다. 사이트가 돌려주는 alert 문구를 믿지 않고,
제출 후 **다시 조회해서 그 시간에 예약이 실제로 잡혔는지 확인한 뒤에만** "예약 확인됨"으로 표시합니다.
확인이 안 되면 `⚠ 제출은 됐지만 예약을 확인하지 못했습니다` 로 경고합니다(중복 예약 주의).

**실패하면 이유도 자동으로 확인합니다.** API 키가 있으면 저장 응답에서 제출 전과 달라진 부분만
추려(보통 300바이트 남짓) Claude 에게 보내고, 사이트가 거부한 것인지 / 저장은 됐는데 목록에
안 뜨는 것인지 / 알 수 없는지를 원인과 함께 화면에 보여줍니다.
**예약 여부 판정은 재조회가 하고, 모델은 이유만 설명합니다** — 모델 판단이 결정적 검증을
덮어쓰면 신뢰도가 떨어지기 때문입니다. 키도 CLI 도 없으면 대신 **보낸 값과 응답에 남은 값을
나란히 적은 요약**을 `meetingroom-save-response.txt` 로 저장합니다(예전에는 응답 HTML 을
통째로 100KB 넘게 적었는데, 실제로 원인을 가리키는 건 이 값 대조뿐이라 요약만 남깁니다).

저장 전에 회의실 선택이 실제로 반영됐는지도 확인하고, 다르면 제출을 중단합니다.

## 아직 확인이 필요한 것

**다른 날짜로 이동**은 Telerik RadCalendar 포스트백이라 인자 형식을 캡처만으로는 알 수 없어,
후보를 차례로 시도하고 `LB_DATE` 로 성공을 판정합니다. 오늘 날짜는 기본값이라 항상 동작하고,
다른 날짜는 `◀ ▶` 를 눌러봐야 확인됩니다. 실패하면 조용히 틀리지 않고 **확인 불가**로 표시됩니다.

**차량 신청·취소를 실제로 보내 본 적은 없습니다.** 신청 폼 구조는 실제 캡처와 CDP 로 확인했고
(`test/carform-real.test.mjs`, `test/cdp/run.mjs`), 보낼 값과 필수 조건도 사이트의
`fnSaveCheck()` 와 맞춰 두었고, **2026-09-30 에 신청 → 확인 → 취소까지 실제로 한 바퀴
돌려봤습니다**(사이트 응답: "예약이 완료 되었습니다", 재조회로 확인, 곧바로 취소).
실패하면 제출 여부와 이유를 그대로 말하고, 확인이 안 되면 `⚠` 로 경고합니다.

**차량 취소도 2026-09-30 에 실제로 확인했습니다.** 그때까지는 2026-09-16 캡처에 본인 차량
예약이 없어 삭제 버튼 마크업을 대조하지 못했고, 그래서 엉뚱한 길(`fn_del` 인자)을 찾고
있었습니다. 지금은 행에 붙은 취소 submit 버튼을 쓰고, 취소 뒤에는 반드시 재조회로
사라졌는지 확인합니다.
